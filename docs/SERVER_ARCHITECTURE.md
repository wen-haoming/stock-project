## 四、核心业务流程

### 4.1 区间涨幅查询流程

```
┌──────────────────────────────────────────────────────────────────┐
│                    区间涨幅查询流程                               │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  1. 接收请求参数                                                  │
│     start_date, end_date, market, min_change_pct, etc.          │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  2. 检查内存缓存 (MemoryCache)                                    │
│     - Key: market:start_date:end_date                           │
│     - 命中 → 直接返回                                            │
└──────────────────────────────────────────────────────────────────┘
                              │ 未命中
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  3. 检查 MongoDB 缓存 (range_cache 集合)                          │
│     - 命中 → 加载到内存缓存 → 返回                                │
└──────────────────────────────────────────────────────────────────┘
                              │ 未命中
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  4. MongoDB 聚合计算                                              │
│     - 从 klines_a/klines_hk 表查询                               │
│     - 聚合管道: $match → $sort → $group → $project               │
│     - 计算: changePct = (endPrice - startPrice) / startPrice    │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  5. 合并股票基础信息                                              │
│     - 从 stocks_a/stocks_hk 获取: 名称、市值、PE/PB、行业等       │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  6. 写入缓存                                                      │
│     - 写入 MongoDB 缓存                                          │
│     - 写入内存缓存                                                │
│     - 缓存TTL根据查询日期动态计算                                 │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  7. 过滤并返回                                                    │
│     - 按涨幅、市值、行业过滤                                      │
│     - 按涨幅降序排序                                              │
└──────────────────────────────────────────────────────────────────┘
```

### 4.2 数据同步流程

```
┌──────────────────────────────────────────────────────────────────┐
│                      服务启动同步流程                             │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  1. 初始同步 (initialSync)                                       │
│     - 同步A股股票列表 → stocks_a                                 │
│     - 同步港股股票列表 → stocks_hk                               │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  2. K线智能同步检查 (checkAndSyncKlines)                         │
│     - 检查 klines_a 和 klines_hk 是否有数据                      │
└──────────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
        ┌──────────┐                   ┌──────────────┐
        │ 无数据    │                   │ 有数据       │
        │ 全量同步  │                   │ 智能同步     │
        └──────────┘                   └──────────────┘
                                              │
                                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  3. 智能同步逻辑 (syncHistoryDataSmart)                          │
│     - 获取全局最新K线日期                                         │
│     - 计算距今缺失的交易日天数                                    │
└──────────────────────────────────────────────────────────────────┘
                              │
      ┌───────────────────────┼───────────────────────┐
      ▼                       ▼                       ▼
┌──────────┐           ┌──────────┐           ┌──────────┐
│ 缺失0天   │           │ 缺失N天   │           │ 缺失>365天│
│ 无需同步  │           │ 同步N+3天 │           │ 全量同步  │
└──────────┘           └──────────┘           └──────────┘

示例：
- 最新K线日期: 2024-12-25, 今天: 2024-12-27 → 缺失约1个交易日 → 同步4天
- 最新K线日期: 2024-12-20, 今天: 2024-12-27 → 缺失约5个交易日 → 同步8天
- 最新K线日期: 2024-01-01, 今天: 2024-12-27 → 缺失>365天 → 全量同步
```

### 4.3 定时任务调度

```
┌──────────────────────────────────────────────────────────────────┐
│                        定时任务调度                               │
└──────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  每分钟检查                                                      │
│  ├── 交易时间 && 每5分钟 → 同步实时数据 (股票列表)               │
│  ├── 凌晨2点 → 增量同步历史K线                                   │
│  └── 凌晨3点 → 清理7天前旧缓存                                   │
└─────────────────────────────────────────────────────────────────┘

交易时间定义:
┌─────────────────────────────────────────────────────────────────┐
│  A股: 09:30-11:30, 13:00-15:00 (周一至周五)                      │
│  港股: 09:30-12:00, 13:00-16:00 (周一至周五)                      │
└─────────────────────────────────────────────────────────────────┘
```

## 六、缓存策略

### 6.1 缓存层级

```
┌─────────────────────────────────────────────────────────────────┐
│  第一层: 内存缓存 (MemoryCache)                                  │
│  - LRU策略，最大1000条                                          │
│  - 自动清理过期条目                                              │
│  - 最快响应，毫秒级                                              │
└─────────────────────────────────────────────────────────────────┘
                              │ 未命中
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  第二层: MongoDB缓存 (range_cache集合)                           │
│  - 持久化存储                                                    │
│  - 服务重启后仍可用                                              │
│  - 响应时间: 10-50ms                                             │
└─────────────────────────────────────────────────────────────────┘
                              │ 未命中
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  第三层: 实时计算                                                │
│  - MongoDB聚合查询                                               │
│  - 响应时间: 100ms-数秒                                          │
│  - 计算后写入上层缓存                                            │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 缓存TTL策略

| 场景 | TTL | 说明 |
|------|-----|------|
| 纯历史数据 | 24小时 | end_date < 今天 |
| 包含当天 + 交易中 | 15分钟 | end_date = 今天 && 交易时间内 |
| 包含当天 + 收盘后 | 4小时 | end_date = 今天 && 收盘后 |

## 十、错误处理

### 10.1 HTTP 响应格式

```json
// 成功
{
    "code": 0,
    "data": [...],
    "total": 100
}

// 失败
{
    "code": -1,
    "error": "错误信息"
}
```

### 10.2 Recovery 中间件

- 捕获所有 panic
- 记录错误日志
- 返回 500 状态码
- 不暴露内部错误详情
